24.枚举

枚举（Enumeration）是C++中一种用户定义的类型，它允许开发者为程序中的整型常量赋予更易读的名字。枚举用于表示一组有限的、相关的值。使用枚举可以使代码更加清晰、更易于维护，同时也提高了类型安全。

枚举的优势

  • 可读性和可维护性：枚举使代码更易于阅读和维护，因为它们通过名称而不是数字来表示状态和常量。
  • 类型安全：特别是对于作用域枚举，它们提高了类型安全，避免了意外的隐式类型转换。
  • 命名空间管理：作用域枚举通过其枚举类型管理其值的命名空间，避免了全局命名空间污染。
  • 与整型值互操作：尽管作用域枚举不会隐式转换为整数，但可以通过显式类型转换来与整型值互操作，增加了灵活性。

使用场景

  • 表示一组相关的常量值：当你有一组密切相关的常量（如颜色、方向、状态码）时，使用枚举可以清晰地表达这种关系。
  • 状态机：在表示有限状态机的状态时，枚举是一个很好的选择。
  • 选项和配置：当函数或类需要一组特定的选项或配置时，枚举可以作为参数传递，提高代码的清晰度和类型安全。

枚举是C++中一种强大的工具，能够提高代码的清晰度、可读性和类型安全性。正确地使用枚举可以大大增强程序的表达力。

26.析构函数

析构函数是一个特殊的成员函数，在对象的生命周期结束时被自动调用，用来执行对象销毁前的清理工作。它的名称由波浪号后跟类名组成（例如，对于类ClassName，析构函数将是~ClassName()）。析构函数不能有参数，因此不能被重载，每个类只能有一个析构函数。

为什么要使用析构函数：

  1. 资源释放：在使用动态分配的内存（例如，使用new操作符），打开文件、数据库连接，或其他需要显式释放或关闭的资源时，析构函数是释放这些资源的理想位置。这确保了即使发生异常，资源也能被适当地管理和释放，防止内存泄露和资源泄露。

  2. 对象销毁前的清理工作：除了资源释放，析构函数也可以用来执行任何必要的最后一步操作，比如关闭日志文件、发送对象被销毁的通知、减少引用计数等。

  3. 自动化管理：析构函数的自动调用简化了资源管理。开发者不需要手动调用清理函数或记住释放资源。这降低了编程错误的可能性，提高了代码的安全性和可维护性。

  4. 实现RAII（资源获取即初始化）：RAII是现代C++编程中管理资源、异常安全性的关键技术。通过将资源的生命周期绑定到对象的生命周期，当对象被销毁时，其析构函数确保所有资源都被适当释放。这种模式在标准库中广泛使用，如std::vector、std::string、智能指针等。

析构函数是C++资源管理和对象生命周期管理中不可或缺的一部分。合理使用析构函数可以使代码更健壮、更易于管理，并减少内存和资源的泄露。

27.继承

继承是面向对象编程（OOP）的一个核心概念，允许创建基于现有类的新类，从而实现代码的重用、扩展和模块化。在C++中，继承使得一个类（称为派生类或子类）可以继承另一个类（称为基类或父类）的成员（包括数据成员和方法）。

基本概念

  • 基类（父类）：被继承的类，提供了可被派生类继承的属性和方法。
  • 派生类（子类）：继承基类的类，可以添加新的属性和方法，也可以重写（override）基类中的方法。

继承的类型

C++支持几种类型的继承：

  1. 公有继承（Public Inheritance）：基类的公有成员和保护成员在派生类中保持其原有的状态，基类的私有成员也被继承，但不能直接访问，只能通过基类提供的公有或保护成员函数访问。
  2. 保护继承（Protected Inheritance）：基类的公有成员和保护成员在派生类中变成保护成员。
  3. 私有继承（Private Inheritance）：基类的公有成员和保护成员在派生类中变成私有成员。

继承的特点

  • 代码重用：继承允许派生类重用基类的方法和属性，减少代码重复。
  • 多态：通过继承和基类的指针或引用，可以实现多态。多态允许我们通过基类的指针或引用来调用派生类的方法。
  • 可扩展性：继承使得新的类可以在不修改现有类的基础上进行扩展，增加新的功能。

使用继承的注意事项

  • 避免过度使用继承：不恰当的继承关系会使得代码变得复杂，维护成本增加。应优先考虑组合（composition）或聚合（aggregation）等其他关系。
  • 注意构造函数和析构函数的调用顺序：在创建派生类对象时，先调用基类的构造函数，然后是派生类的构造函数；销毁对象时顺序相反，先调用派生类的析构函数，再调用基类的析构函数。
  • 虚继承：在多重继承时，为了解决菱形问题（diamond problem），可以使用虚继承使得某个类在继承链中只有一个实例。

继承是实现面向对象设计原则（如DIP、LSP等）和设计模式（如工厂模式、策略模式等）的基础之一，正确理解和使用继承对于设计健壮、灵活的系统至关重要。

28.虚函数

虚函数在C++中是一个关键概念，主要用于实现多态性。通过虚函数，可以在基类中声明一个函数为虚拟的，允许派生类根据需要重写（override）该函数，而调用该函数时将根据对象的实际类型来决定调用哪个版本的函数。这意味着即使有一个基类指针或引用指向派生类的对象，当通过这个指针或引用调用虚函数时，执行的是派生类中重写的函数，而不是基类中的原始版本。

29.纯虚函数

纯虚函数是C++中实现抽象类的一个机制，其目的是定义一个接口，强制派生类提供特定功能的实现。纯虚函数在基类中声明，但不提供实现（即，函数体为空），而是在派生类中实现。一个类如果包含至少一个纯虚函数，则称为抽象基类（Abstract Base Class, ABC）。抽象基类不能被实例化，它主要用于定义派生类应遵循的接口协议。

纯虚函数的目的和用途

  • 定义接口协议：纯虚函数允许开发者在基类中定义一个接口。派生类必须实现这个接口，否则它们也会成为抽象类，不能被实例化。
  • 实现多态性：纯虚函数支持多态性，即在运行时根据对象的实际类型调用相应的函数。这允许用基类的引用或指针来操作派生类的对象，而调用的是派生类中重写的函数版本。
  • 促进代码重用和扩展性：通过定义通用的接口，不同的派生类可以实现相同的接口但提供不同的实现。这有助于代码的重用和扩展。

使用纯虚函数的注意点

  • 抽象基类不能被实例化：因为至少有一个函数没有实现，所以不能创建抽象基类的对象。
  • 派生类必须实现所有纯虚函数：派生类必须提供所有纯虚函数的实现，否则它也将成为抽象类。
  • 抽象基类可以包含非纯虚函数：抽象基类除了可以有纯虚函数外，还可以包含非纯虚函数（即有实现的函数），以提供一些基本的功能或默认行为。

纯虚函数和抽象基类是实现接口和多态性的强大工具，它们在设计复杂系统和框架时尤其有用，可以提供清晰的架构和灵活的实现策略。

30.可见性

C++中的可见性（或称访问控制）是面向对象编程的一个重要概念，它决定了类成员（包括数据成员和成员函数）的访问权限。C++提供了三种主要的访问控制级别：public、protected和private，用来定义类成员的可见性范围。这些访问控制符决定了类的接口与实现的分离，以及类的封装性。

public 成员

  • 定义：如果类成员被声明为public，则意味着这些成员可以在任何地方被访问，无论是类的内部还是外部。
  • 用途：通常用于定义类的接口部分，即那些可以被外部代码直接使用的函数和数据成员。

protected 成员

  • 定义：protected成员在类的内部和派生类（子类）中是可访问的，但在类的外部是不可访问的。
  • 用途：这种访问级别用于当你希望只有类本身和它的派生类能访问某些成员时。protected成员通常用于实现继承时的成员变量或函数。

private 成员

  • 定义：如果类成员被声明为private，它们只能被该类的成员函数、友元函数访问，对于类的外部以及派生类都是不可见的。
  • 用途：private成员用于类的实现细节，隐藏了类的内部状态，防止外部代码直接访问对象的内部数据。

40.隐式转换与explicit关键字

隐式转换只进行一次

在 C++ 中，隐式转换（也称为隐式类型转换）通常只能进行一次。这意味着在将一个类型的值转换为另一个类型的值时，编译器仅尝试应用一次隐式转换规则。如果需要多次转换才能从源类型到达目标类型，那么这种转换必须至少部分地显式进行，否则会导致编译错误。

explicit

  • 在 C++ 中，explicit 关键字用于防止类构造函数的隐式自动转换。默认情况下，如果一个构造函数只接受一个参数，或者所有参数除了第一个外都有默认值，那么它可以被用作隐式转换操作符。这种隐式转换可能会在不期望的情况下发生，导致难以追踪的错误。使用 explicit 关键字可以要求在进行转换时必须显式地使用构造函数。

41.运算符及其重载

运算符重载基本原则

  1. 提高可读性和易用性：运算符重载应该使代码更加直观易懂，不应该引入歧义或复杂性。
  2. 保持运算符原有的语义：重载的运算符应该与原运算符保持相似的语义，避免混淆。
  3. 不能改变运算符的优先级：重载不会改变运算符的优先级和结合性。

43. 栈作用域生存期

  • 在 C++ 中，栈作用域生存期（Stack Scope Lifetime）指的是局部变量在程序执行流进入定义它们的代码块时被创建（分配内存），并在执行流离开该代码块时被销毁（释放内存）的特性。这种生存期与变量的存储位置（栈）和作用域（通常是一个函数或代码块内部）紧密相关。

栈作用域的特点

  • 自动存储期：栈作用域变量具有自动存储期，意味着它们无需手动创建和销毁，这些操作由编译器自动完成。
  • 有限的访问范围：只能在定义它们的代码块内访问这些变量。一旦执行流离开该代码块，这些变量就不再存在，尝试访问它们将导致未定义行为。
  • 快速分配和回收：在栈上分配内存通常非常快速，因为它仅涉及到移动栈指针。相比之下，在堆上分配内存需要更复杂的内存管理操作。

示例

广泛应用

  1. 自动资源管理（RAII）
    RAII（Resource Acquisition Is Initialization）是一种利用局部变量生存期自动管理资源（如内存、文件句柄、锁等）的技术。当对象在栈上创建时，其构造函数自动获取资源，当对象的生存期结束时，其析构函数自动释放资源。这样，即使发生异常或提前返回，资源也总会被正确释放，避免了资源泄漏。

  2. 简化内存管理
    栈分配的速度远快于堆分配，因为栈分配通常只涉及指针的简单移动。此外，栈上的对象无需显式删除，它们会在离开作用域时自动被销毁。这简化了内存管理，避免了复杂的堆内存分配和释放逻辑，减少了内存泄漏和指针悬挂的风险。

  3. 支持作用域基的编程
    栈作用域生存期支持作用域基的编程模式，其中变量的可见性和生命周期被限制在定义它们的代码块内。这有助于提高程序的模块性和可读性，减少变量名冲突，以及限制变量的访问范围，从而减少错误。

  4. 实现确定性的资源回收
    与堆分配的对象（其生命周期需要显式管理）相比，栈上的对象提供了确定性的资源回收。这意味着程序员可以精确知道对象何时被创建和销毁，这对于需要精确控制资源生命周期的应用（如实时系统、游戏开发等）非常重要。

  5. 支持临时对象和返回值优化
    在函数调用中使用临时对象时，栈作用域生存期允许这些对象在不再需要时立即被销毁。此外，现代 C++ 编译器利用返回值优化（RVO）和命名返回值优化（NRVO）技术，可以在函数返回时避免不必要的复制，这些都依赖于栈作用域对象的行为。

注意事项

  • 尽管栈作用域变量在使用上简单方便，但它们的生存期限制了它们的用途。特别是，不能将栈作用域变量的地址返回给函数外部，因为它们在函数返回后就不再有效。
  • 栈空间是有限的。过多的栈分配或非常大的栈变量可能导致栈溢出。

44.智能指针

  • 智能指针是 C++ 标准库中提供的一种模板类，用于管理动态分配的内存，以确保资源得到适当管理。智能指针的主要目的是自动化资源的分配和释放，避免内存泄漏，同时提供对原始指针类似的操作。C++11 引入了几种类型的智能指针，主要包括 std::unique_ptr、std::shared_ptr 和 std::weak_ptr。

std::unique_ptr

  • std::unique_ptr 是一种独占所有权的智能指针，意味着同一时间内只能有一个 std::unique_ptr 指向给定的对象。当 std::unique_ptr 离开作用域时，它所指向的对象会被自动销毁。这种智能指针不能被复制，但可以通过移动语义转移其所有权。

std::shared_ptr

  • std::shared_ptr 是一种共享所有权的智能指针。多个 std::shared_ptr 可以指向同一个对象，内部使用引用计数来跟踪有多少个智能指针共享同一个资源。当最后一个指向对象的 std::shared_ptr 被销毁时，或者被重新赋予新的对象时，原对象会被自动删除。

std::weak_ptr

  • std::weak_ptr 是一种不控制对象生命周期的智能指针，它被设计来解决 std::shared_ptr 之间的循环引用问题。std::weak_ptr 指向一个由 std::shared_ptr 管理的对象，但不增加对象的引用计数。通过 std::weak_ptr，你可以访问对象，但需要先将其转换为 std::shared_ptr 来确保对象仍然存在。

智能指针的用途

  • 自动管理动态分配的内存，避免内存泄漏。
  • 简化资源所有权和生命周期的管理。
  • 支持更复杂的数据结构，如共享数据和循环引用结构。

智能指针是现代 C++ 开发中管理资源和提高代码安全性的重要工具。正确使用智能指针可以减少直接使用原始指针相关的许多常见错误，使资源管理更加安全和可靠。

  • 删除元素：pop_back 删除最后一个元素，erase 删除指定位置或范围内的元素。

54.栈与堆内存的比较

栈内存(Stack)

  • 自动管理：栈内存由编译器自动管理。局部变量和函数调用的参数通常存储在栈上。
  • 后进先出：栈遵循后进先出（LIFO）的原则。函数调用时创建局部变量，函数返回时销毁这些局部变量。
  • 速度快：栈内存的分配和回收速度非常快，因为它仅涉及到指针的移动。
  • 大小限制：栈的大小相对较小，受限于操作系统和程序的设置。大量的数据或大型对象应避免在栈上分配。
  • 安全性：栈内存相对安全，因为每个线程有自己的栈空间，且内存自动管理减少了泄露的风险。

堆内存(Heap)

  • 动态分配：堆内存的分配和释放是手动管理的（通过 new/delete 在 C++ 或 malloc/free 在 C 中）。可以在任意时刻分配和释放内存。
  • 灵活性：堆允许动态分配大量内存，适用于生命周期长或大小不确定的对象。
  • 访问速度较慢：与栈相比，堆内存的分配和回收速度较慢，且容易产生内存碎片。
  • 容易出错：手动管理堆内存容易出现错误，如内存泄露、重复释放等。
  • 全局访问：堆内存是由所有线程共享的，适合存储需要跨函数或模块访问的数据。

总结

  • 管理方式：栈内存的管理是自动的，堆内存需要程序员手动管理。
  • 生命周期：栈内存中的对象通常在所在函数调用结束时自动销毁；堆内存中的对象需要显式删除，否则会持续存在。
  • 性能：栈内存的分配和回收速度快，堆内存操作相对较慢，但提供了更大的灵活性和容量。
  • 用途：栈适用于存储函数内的局部变量和控制流信息；堆适用于存储生命周期长或大小需动态确定的数据。

在实际编程中，正确选择堆和栈对于程序的性能和稳定性至关重要。简单的、短生命周期的数据应该使用栈，而复杂的、生命周期长或需要全局访问的数据则应该使用堆。

65.排序(std::sort)

  • std::sort 是 C++ 标准库中定义于 <algorithm> 头文件中的一个非常强大的排序函数。它能够对给定范围内的元素进行排序，默认情况下是按升序排列。std::sort 使用的排序算法取决于具体的实现，但通常是快速排序、堆排序或其他 O(nlogn) 复杂度的高效排序算法的变种。
  • 基本用法：std::sort 函数至少需要两个参数：指定要排序的元素范围的开始和结束迭代器。可选的第三个参数是一个比较函数，用于自定义排序准则。
  • 比较函数：std::sort 的第三个参数是一个可选的比较函数，它接收两个元素作为参数，返回一个布尔值。如果第一个元素应该排在第二个元素之前，则返回 true；否则返回 false。这允许进行自定义排序逻辑，如按降序排序或根据对象的某个属性排序。
  • 性能和复杂度: std::sort 通常非常高效，其时间复杂度大多数情况下为 O(nlogn)，其中 n 是要排序的元素数量。然而，具体的性能也取决于数据的初始状态、所用的比较函数的复杂度以及实现细节。
  • std::sort是不稳定排序，对于需要稳定排序的场景，应使用 std::stable_sort。

66.类型双关（Type punning）

  • 类型双关（Type punning）是一种编程技巧，用于以一种类型的解释方式访问另一种类型的数据。这通常涉及到绕过类型系统的严格性，直接操作底层的二进制表示。类型双关在某些特定场景下非常有用，比如硬件编程、优化、或处理复杂的数据结构时，但它也可能引入未定义行为，因此需要谨慎使用。

1. union 使用

  • 通过 union 实现类型双关是一种相对安全的方式，因为 union 允许以多种类型来访问同一块内存。不过，根据 C++ 标准，除非当前激活的成员类型与访问的类型相同，否则访问 union 的非激活成员是未定义行为。

2. 类型转换

  • reinterpret_cast：这种类型转换允许将一种指针类型转换为另一种指针类型，甚至是不相关的类型，它基本上是对地址的直接重新解释。使用 reinterpret_cast 进行类型转换可能会破坏对象的对齐要求，引入未定义行为。
  • 指针类型转换：通过将数据的地址取出，转换为另一类型的指针，然后解引用访问。

3. std::memcpy

  • std::memcpy 可以用来在不同类型之间安全地复制数据，因为它逐字节地复制内存，不关心具体的类型。这种方式不会引入未定义行为，但仍需确保目标类型的大小足够容纳源类型的数据。

67.联合体(union)

在C++中，union是一种特殊的数据类型，允许在相同的内存位置存储不同的数据类型。union的特点是它的所有成员共享同一块内存区域，因此union的大小等于其最大成员的大小。

在这个例子中，因为struct1和struct2的大小相同（假设没有额外的内存对齐造成的空间增加），union的大小将会是12字节，这意味着union ExampleUnion的所有成员都共享这12字节的内存。因此，当你往struct1的x和y写入数据时，实际上是在修改这12字节内存的前部分（对于x）和后部分（对于y）；而当你通过struct2的c数组访问这块内存时，你是在以字符数组的形式访问相同的内存区域。

需要注意的是，由于int加double的总大小与字符数组c[12]在此例中恰好相等，并且假设没有因内存对齐导致的大小差异，这种情况下你可以说c[12]占用了等同于int加double所需内存的空间。但实际应用中，特别是涉及不同类型或需要内存对齐的情况，union的总大小可能会因为最大成员而更大，也可能因编译器或平台的内存对齐策略而有所不同。

总之，union中的所有成员共享同一块内存，union的总大小由其最大成员的大小（考虑内存对齐）决定。在操作union时，修改任何一个成员的内容都可能影响到其他成员如何解释这块共享内存。

68.虚析构函数

  • 在 C++ 中，虚析构函数是一种特殊的析构函数，用于正确清理继承体系中派生类对象的资源。当删除指向派生类对象的基类指针时，虚析构函数确保调用正确的析构函数，无论是基类的还是派生类的，从而防止资源泄露。

为什么需要虚析构函数？

  • 考虑一个带有基类和派生类的情况，如果基类的析构函数不是虚的，那么通过基类指针删除派生类对象时，只会调用基类的析构函数，而不会调用派生类的析构函数。这可能导致派生类分配的资源没有被正确释放，引起资源泄露。

69.类型转换

  • 在 C++ 中，类型转换用于将一个数据类型的变量转换为另一个数据类型。C++ 提供了几种类型转换方式，包括隐式转换、显式转换（C 风格和 C++ 风格）和类型转换运算符。

隐式转换

  • 隐式转换是编译器自动进行的转换，不需要程序员手动干预。例如，将 int 类型赋值给 float 类型时，就会发生隐式转换。

显式转换

C 风格转换

  • C 风格的类型转换使用 (类型名)表达式 的语法，可以转换大多数类型，但其不安全性和可读性较差。

C++ 风格转换

**1. static_cast<类型名>(表达式)**：static_cast 是最常用的类型转换运算符，适用于大多数具有明确语义的转换，包括基本数据类型之间的转换、对象之间的上行转换（派生类指针或引用转换为基类指针或引用）。

**2. dynamic_cast<类型名>(表达式)**：dynamic_cast 用于对象之间的下行转换（基类指针或引用转换为派生类指针或引用）和跨层次转换。这种转换在运行时检查类型兼容性，如果失败，指针类型转换返回 nullptr，引用类型转换抛出 std::bad_cast 异常。这要求基类至少有一个虚函数。

**3. const_cast<类型名>(表达式)**：const_cast 用于改变对象的 const 或 volatile 属性，最常见的用途是去除 const 属性。它不能改变对象的本质类型。

**4. reinterpret_cast<类型名>(表达式)**：reinterpret_cast 提供了低级别的重新解释转换，用于位模式的直接转换。它可以在几乎任何指针类型之间转换，以及指针与足够大的整数类型之间转换。使用时需要特别小心，因为这种转换的安全性完全由程序员负责。

高级特性

注意事项

  • 结构化绑定创建的变量实际上是对原始数据的引用，而不是拷贝（除非显式要求复制）。这意味着如果你修改了绑定的变量，原始数据也会相应被修改（如果变量不是 const）。

  • 结构化绑定还支持解包 std::pair 和 std::array。

90.移动语义(std::move)

std::move 实际上并不移动任何东西，也不修改对象本身的内容。它只是将其参数转换为右值引用，这使得使用 std::move 的对象可以作为移动构造函数或移动赋值操作符的输入。换句话说，std::move 告诉编译器我们有一个对象，我们打算不再使用它当前的状态，而是希望将其资源“移动”到另一个对象中。移动操作的具体行为取决于移动构造函数或移动赋值操作符的实现。

关于“偷资源”的理解

当我们说移动构造函数或移动赋值操作符“偷走”了资源，我们是指它们接管了被移动对象的内部资源（如动态分配的内存、文件句柄、套接字等），并将这些资源的所有权转移到新对象中。这通常涉及到：

  • 将资源的指针或句柄从一个对象复制到另一个对象。
  • 将原对象的相应指针或句柄设置为 nullptr 或其它无效状态，确保原对象析构时不会释放这些已经转移走的资源。

与普通指针赋值的区别

当你将一个指针赋值给另一个指针时，你确实是让两个指针指向了同一块内存或资源。这与移动语义下的“偷资源”行为是不同的。在后者中，资源的所有权被转移，原来拥有资源的对象失去了对它的所有权，这意味着：

  • 移动后，原对象不应再使用这些资源。
  • 原对象在析构时不会尝试释放已经转移的资源，避免了双重释放的风险。

在使用指针赋值的情况下，如果两个指针都尝试释放指向的内存，就会发生双重释放的错误。这就是为什么在处理原始指针时，复制指针（导致两个指针指向同一资源）和移动资源（转移所有权）之间的区别非常重要。在现代 C++ 编程中，推荐使用智能指针（如 std::unique_ptr 和 std::shared_ptr）来自动管理资源，以避免这类问题。
